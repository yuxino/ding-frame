# ADR 0001：采用临时处理链路，不建立永久视频库

## 状态

已接受。

## 背景

盯帧的第一版目标是分析小视频，而不是管理视频资产。用户明确希望“阅后即焚”，也不希望视频分析占用个人电脑的持久空间。

## 决策

服务端使用操作系统临时目录承接上传或 URL 下载；抽帧和文本结果仅存在于进程内存与任务临时目录。分析完成后立即删除原视频和中间音频，结果与抽帧在短 TTL 后整体删除。ASR 将临时 MP3 切片以 Base64 直接发送给 Qwen3-ASR-Flash，不建立 OSS Bucket，也不产生独立远程文件生命周期。

## 取舍

- 优点：数据生命周期清晰、早期不需要数据库、部署简单，符合“看一遍就消失”。
- 代价：服务重启后任务消失；多实例部署无法共享任务和结果；结果过期后不可恢复。
- 后续如果需要并发和历史记录，应引入 Redis/队列与明确的持久化授权，而不是悄悄改变当前语义。
